# Acceptance Criteria v1.0

Selection of critical scenarios that **MUST** pass before release 1.0. "Stage" = earliest stage in
which the criterion can be verified ([roadmap.md](roadmap.md)).

| ID | Scenario | Criterion | Related | Stage |
|---|---|---|---|---|
| AC-01 | Plugin extension | Adding a sample new question type to the deployment without changing kernel code; editor, validation, rendering and evaluation register correctly. | ADR-0002, ADR-0021, FR-16 | A |
| AC-02 | Auth/persistence | A test-only alternative authentication provider passes the same contract test suite; switching happens on restart, never uncontrolled at runtime. Persistence contract tests run against the SQLite provider; a second persistence provider is LATER. | ADR-0036, ADR-0027 | A |
| AC-03 | Translations | A `cs+uk` quiz can be published only with complete translations; English is not required unless enabled for the quiz. | FR-03, ADR-0018 | B |
| AC-04 | Revisions | Participant starts an attempt on revision 1, admin publishes revision 2; the submission is evaluated against revision 1 and stays in history. | FR-09, FR-19, ADR-0006 | B |
| AC-05 | Run repeat | After close and restart a new `run_id` exists, the new run's public scoreboard is empty, the old run's results are viewable in admin (unless retention expired). | FR-12, ADR-0007 | C |
| AC-06 | Revision merge | With different max points a common scoreboard cannot be enabled; with equal max points the admin sees the differences between revisions and can knowingly enable it, which is audited. | FR-30, ADR-0008 | C |
| AC-07 | Deadline | Server rejects submission after deadline even with the browser kept open; without deadline submission works until manual close. With limit 10:00:00, a submission received at 10:00:00.9 is accepted and at 10:00:01.0 rejected. | FR-11, ADR-0010, ADR-0025 | C |
| AC-08 | Tampering | Modified `score`, `started_at`, `revision_id` or manifest in the client payload do not affect the result or cause rejection. | ADR-0009, ADR-0024 | A |
| AC-09 | No retention | After submission the participant sees the score, but no result or participant PII is created in the DB; scoreboard and draw are unavailable. | FR-31, ADR-0012 | C |
| AC-10 | Scoring & thresholds | Five equally weighted questions, 4 correct = 80 %; a 90 % threshold reward is not granted. | FR-25, FR-26 | C |
| AC-11 | Resume | An in-progress attempt can be restored locally in the same browser; start time and assigned questions cannot be changed. | FR-22, ADR-0020 | C |
| AC-12 | Draw | Test attempts are excluded; admin sees the eligible snapshot, audit and history of repeated draws; drawing is never automatic. | FR-13, FR-37, FR-38, ADR-0013 | C |
| AC-13 | Import | A multi-language CSV with errors imports as a draft, errors listed per row, media referenced by URL are not confused with local files. | FR-40, FR-41, ADR-0019 | B |
| AC-14 | Retention | The job deletes/anonymises data after the configured period and keeps permissible non-personal metadata; an older run does not disappear just because a new one was created. | FR-34, ADR-0012 | D |
| AC-15 | Operations | Simulation of 50 concurrent participants including simultaneous submissions with images causes no lost results, no duplicate write of the same attempt and no unhandled DB lock errors; restore from backup verified. | ADR-0005, ADR-0015 | D |
| AC-16 | Image answer | Grading, privacy and upload are B6: a question with 2 automatic and 0–8 manual points shows 2 of 10 after submission and the attempt is pending. A disguised file is rejected and EXIF is removed. A 15 MB phone photo is accepted and stored as at most 700 KB; after the per-run limit further images are refused. Stage C: the public scoreboard is hidden, the draw refused and thresholds not evaluated until grading finishes. | FR-45, ADR-0033, ADR-0028, ADR-0047 | B6, C |
| AC-17 | Module requirements | Selecting a module shows its required settings; a conflicting setting blocks publication with an explanation; satisfying it allows publication. | FR-46, ADR-0034, refined by AC-61 | B6 |
| AC-18 | Immediate solutions | Enabling reveal after each question in a run with a visible scoreboard or rewards is blocked with an explanation; in a run without them the participant sees the solution after each question. | FR-23, ADR-0035 | B |
| AC-19 | Revision switch | With `notify_switch`, a participant in progress sees the notice within one polling interval; after "Switch", answers to unchanged questions are kept, changed ones are empty and marked, the old attempt can no longer be submitted, start time is unchanged and a double click creates one attempt. With `let_finish`, an attempt in progress submits on the old revision while new starts get the new one. `stay` leaves the round on the old revision and the next round opens on the new one. | FR-47, ADR-0038 | B |
| AC-20 | Settings override | A quiz override beats the global setting; deleting the override returns to the global value; saving it creates no draft. | FR-50, ADR-0038 | B |
| AC-21 | Change overview | The publication page shows a changed correct answer; publishing a quiz changed after the page was shown is refused. | FR-48 | B |
| AC-22 | Return and archive | Returning to an older revision creates a new number and leaves the old revision unchanged (same checksum). A quiz with an open round cannot be archived; an archived one has no public page and returns on restore. | FR-08, FR-09, FR-49 | B |
| AC-23 | Main button | The main button shows the right label and action in each quiz state; starting a quiz with changes shows the overview, then publishes and opens a run together, or does neither. | FR-51 | B |
| AC-24 | Description | A quiz without a description in a selected language cannot be published; an existing published quiz keeps working unchanged. | FR-52 | B |
| AC-25 | Palettes | A palette override changes only that quiz's public pages and creates no draft; deleting it returns to the global value; all five palettes pass the contrast test in both modes. | FR-53 | B |
| AC-26 | Choice | With 3 correct of 5, partial scoring gives right minus wrong, and ticking everything pays no more. A trick question scores only with "None of the answers"; nothing ticked scores zero. With `trick_questions` that answer appears only there, with `all_questions` everywhere except yes/no. | FR-15, FR-24 | B |
| AC-27 | Matching | Pairs and order score as defined, with bottom-up reversing the order. The page does not depend on the correct order. Drag and drop, keyboard and no-JavaScript ordering give the same result. | FR-15 | B |
| AC-28 | Images | A published revision still shows its images. An image without alternative text blocks publication. A file that is not an image, or above the limit, is refused with a message and keeps the rest of the form. Multipart is refused everywhere except the question editor. | FR-21 | B |
| AC-29 | Sources | Sources show on the result when on, and not when off. A line with markup is escaped; only a whole `https://` address becomes a link. | FR-54 | B |
| AC-30 | Draw rows | A row "3 from a bank, 2 points each" gives each attempt 3 distinct questions and the same maximum. Two rows overlapping in one bank never repeat a question. | FR-18, ADR-0041 | B |
| AC-31 | Bank languages | A bank question missing a quiz language is never drawn. Publication is blocked only when the rows cannot be filled. | FR-18, FR-03 | B |
| AC-32 | Bank edits | Editing a bank leaves a published revision and attempts in progress unchanged, and shows unpublished changes on quizzes using it. | FR-08, FR-18, ADR-0041 | B |
| AC-33 | Frozen attempt | An attempt is scored only on what it was given; an answer to another question changes nothing. A settings change does not affect an attempt in progress. | FR-19, ADR-0041 | B |
| AC-34 | Navigation | Each navigation mode works with mouse and keyboard, with a progress indicator; without JavaScript the quiz can be completed on one page. | FR-17, FR-05 | B |
| AC-35 | Reveal | Each moment and level shows exactly what it should. The check request refuses in every other case, and no page contains a correct answer before it is allowed. | FR-23, ADR-0035 | B |
| AC-36 | Reveal conflict | Reveal after each question with all at once is refused in the form; a conflict from a global change falls back to the end, with a warning. | FR-23, ADR-0041 | B |
| AC-37 | Defaults | With all settings at their defaults an existing quiz behaves as before. | FR-17, FR-18, FR-23 | B |
| AC-38 | Address | A valid address stores a copy. The participant's page shows `/media/<id>` and contains no source address. Editing the question without changing the address fetches nothing. | FR-21, ADR-0043 | B |
| AC-39 | Modes | With global `copy`, quiz `external`, question `copy`, the participant gets the copy; removing the question value gives the address. Changing the quiz value creates no draft. | FR-21, ADR-0042, ADR-0043 | B |
| AC-40 | Failed verification | In `copy` the form returns with its data and a message; in `external` the question saves without a copy and warns. Publishing in `copy` is then blocked and names the question. | FR-21, ADR-0043 | B |
| AC-41 | Internal addresses | With the switch off, an internal address and a redirect to one are never fetched; with it on, they are. | FR-21, ADR-0043 | B |
| AC-42 | Check | An unreachable external image shows a warning on the quiz; a second opening within the hour runs no check; a copy-mode quiz runs none and shows none. | FR-21, ADR-0043 | B |
| AC-43 | Settings rule | A module without a `settings` field, or with a narrower scope and no reason, fails the contract tests. Each scope of each setting is offered on its page, and question beats quiz beats global. | ADR-0042 | B |
| AC-44 | Question level | `show_sources`, `shuffle_options` and `none_option` set on one question change that question only. With no question values, an existing quiz behaves as before. | ADR-0042 | B |
| AC-45 | Preview | Clicking through a draft and a published revision in each navigation mode stores nothing: row counts in all tables stay the same. An incomplete draft shows its problems, never a server error. The preview is refused without login. | FR-13, ADR-0044 | B |
| AC-46 | Test isolation | A quiz with test attempts shows the same runs, counts, state and main button as one without. The public page never reaches a test run. Publishing moves no test run. | FR-13, ADR-0044 | B |
| AC-47 | Test links | A link plays its chosen version without login. Changing the draft or publishing leaves a link's version unchanged. A cancelled, expired or invalid link gives the same message, also when submitting from an open page. A draft failing the publication check cannot be sent to test. | FR-13, ADR-0044 | B |
| AC-48 | Test attempts | The admin sees them per link and can delete them. Deleting a link removes its attempts and frozen copy, and nothing else. | FR-13, ADR-0044 | B |
| AC-49 | Import flow | Nothing changes until confirmation. A file with good and bad rows imports the good ones and lists the others with row and column. No quiz or draft is created if no row is usable. | FR-40, FR-41, ADR-0045 | B |
| AC-50 | Sample | The sample with category columns imports as a draft in cs/en/uk with all texts, correct answers, explanations and sources, and reports the category as unused. | FR-40, ADR-0045 | B |
| AC-51 | Import images | An address and a ZIP file are told apart; a missing file is a row error. A failed address keeps the question, warns, and blocks publication in `copy`. The internal-address protection holds. A ZIP over any limit is refused without being unpacked. | FR-40, ADR-0043, ADR-0045 | B |
| AC-52 | Round trip | Export followed by import gives a quiz with the same content, for both question types, images, settings and a text beginning with a formula character. An exported cell never starts with a formula character. | FR-42, ADR-0032, ADR-0045 | B |
| AC-53 | Number | `3,14` equals `3.14`; 1000 with ±5 % accepts 950 and 1050 and refuses 949.99; two separators, `1e5` and `NaN` are refused; a percent tolerance on 0 is refused in the editor. | FR-20 | B6 |
| AC-54 | Text | With markers each blank scores separately and word order differs per language; with none there is one field. Default comparison ignores case and spaces and respects diacritics. With diacritics ignored, `Plzen` equals `Plzeň`, while `и` does not equal `й`. | FR-20 | B6 |
| AC-55 | Split | 10 points with 2 automatic shows 2 of 10 and pending. In a bank, a row of 5 points gives 1 automatic and at most 4 manual. | FR-45, ADR-0047 | B6 |
| AC-56 | Grading | Both views grade and recalculate; the attempt leaves pending when nothing waits; a non-admin cannot grade; each change is audited; a deleted photo is gone, with points at 0. | FR-45, ADR-0047 | B6 |
| AC-57 | Photo privacy | With each level, exactly the right people get a photo. `/media/<id>` answers 404 for it. Public needs approval of that photo and a notice before upload. EXIF is gone. | FR-45, ADR-0047 | B6 |
| AC-58 | Result | The private link shows the final score after grading, and own answers and photo only as settings allow, with no correct answer before reveal. An invalid token logs nothing. The same device shows the link on return. | ADR-0046 | B6 |
| AC-59 | Answers | With `images` only images are stored, and with `all` every answered question. With defaults nothing changes for an existing quiz. `public` without `all` is refused in the form. | ADR-0046 | B6 |
| AC-60 | Walkthrough | It is unavailable during an open run and when neither answers nor photos are public. With public answers it shows counts without any link to a participant, and no test attempt. A hidden value is gone from it. With public photos alone it shows approved photos and no correct answer. | ADR-0046 | B6 |
| AC-61 | Requirements | An image question with `after_each` shows the requirement, offers Use, and blocks publication and opening a run with an explanation; satisfying it allows both. Contradicting requirements block. | FR-46, ADR-0034 | B6 |
| AC-62 | Plan | A run planned with a start opens on the first request after it, with `opened_at` equal to the start and the newest published revision. Before it the address and QR code show the start time and no start button, and the server refuses to start an attempt. One-click start is unchanged. Only one run per quiz is running or planned. | FR-10, ADR-0048 | C |
| AC-63 | Limit | The limit is inherited global → quiz → run, a quiz can drop a global limit, and it cannot change once the run opens. Switching to a new revision gains no time. | FR-10, FR-11, ADR-0048 | C |
| AC-64 | Moved deadline | A running run's deadline can be moved or removed and applies to attempts in progress. A new one under a minute ahead is refused, and moving earlier asks with the number in progress. An open page learns the new time within 30 s. | FR-11, ADR-0048 | C |
| AC-65 | Automatic submission | About 5 s before the end the page submits by itself. An answer or photo that cannot be read counts as unanswered there, and refuses a manual submission as before. A repeat with the same key stores once. A submission received in time counts even after another request closed the run. | FR-11, ADR-0025, ADR-0048 | C |
| AC-66 | Unsent | An attempt that never arrives has no score and counts nowhere. The admin sees how many: on an ended run all in progress, on a running run those past their limit, without replaced attempts. | FR-11, ADR-0048 | C |
| AC-67 | Archive | Only an ended run can be archived, and it can be restored; nothing is deleted. It leaves the list of runs and the public walkthrough and photos, while the private result link and grading keep working. | FR-12, ADR-0048 | C |
| AC-68 | Coming up | A planned quiz is on the public list only when the global setting or the quiz says so, off by default. | FR-10, ADR-0048 | C |
| AC-69 | Time zone | All times are entered and shown in one global zone, default Europe/Prague, and stored in UTC. A time skipped by a clock change is refused, and an ambiguous one takes the first occurrence. The admin sees server and browser time with zones, with a warning over 60 s of difference or on another zone. Test links and a preview with the switch on have the limit and countdown. | FR-10, ADR-0048 | C |
| AC-70 | Repetition | With repeating allowed and the scoreboard hidden no cookie and no participant exist. With it forbidden one browser gets one counted attempt per run, also after a reload, in a new tab or from two tabs at once; the cookie hash differs between runs. | FR-27, FR-28, ADR-0049 | C |
| AC-71 | Unfinished attempt | "Continues" resumes the same attempt, also after a revision switch, and an expired one ends play; "used up" refuses after a start; "counts when submitted" abandons the previous attempt, which no token can submit, switch or check. | FR-27, ADR-0049 | C |
| AC-72 | Access code | Only a hash is stored and no audit row holds the code. The new code is shown once. A run with a code refuses a start without it; ten wrong codes a minute per IP are allowed and the eleventh is refused. A changed code locks out those who have not started while a running attempt resumes. Test links, the walkthrough and the result link need no code, and the QR code holds none. | FR-06, ADR-0030, ADR-0049 | C |
| AC-73 | Name and e-mail | Off, optional or required, asked before the start or at the end. A required field blocks a manual start or submission with the answers kept; an automatic submission is accepted and the result page asks for the missing value. A blank optional field asks nothing later. | FR-32, ADR-0049 | C |
| AC-74 | Duplicate names | With duplicates forbidden, `Žába  Ok` and `žába ok` are one name; of two simultaneous submissions one gets it and the other is refused. An abandoned attempt holds no name, and a name taken during an automatic submission is dropped and can be replaced later. | FR-28, ADR-0049 | C |
| AC-75 | Personal data | The run page lists submitted attempts with name, e-mail, score and time, only after login; an empty name shows "bez jména". No public page, log line or audit row holds a name or e-mail. A preview shows the fields and stores nothing; deleting a test link removes its participants. | FR-32, FR-35, ADR-0049 | C |
| AC-76 | Rules on the run | The six rules are copied from the quiz when a run is planned or opened, can be changed on the plan form, and stay fixed once it opens; a later quiz change does not touch it. | FR-27, FR-32, ADR-0042, ADR-0049 | C |
| AC-77 | Data profile | Each profile keeps exactly what it says: `none` nothing per attempt, `score` score and what a person grades, `answers` every answered question, `detailed` also the duration. The profile is inherited global → quiz, copied onto the run, and fixed once the run opens. The upgrade turns `all` into `answers` and `images` into `score` without changing what an existing run stores. | FR-31, FR-33, ADR-0050 | C |
| AC-78 | Stateless | Under `none` a submission shows the score and leaves no attempt, answer, participant or photo row, only a count that a test run does not raise. A second submission gets a page saying the attempt is over, with no score. The form refuses `none` with repeating forbidden, a name or e-mail asked, visible answers or a photo question, and names the setting. | FR-31, ADR-0050 | C |
| AC-79 | Retention period | A run holds a period of 30, 90 or 180 days, 1 year, 3 years or permanent, 90 days by default, inherited and copied like the profile. It stays editable on a running or ended run. The run page and the privacy page show it, and say deletion arrives in a later version. | FR-34, ADR-0029, ADR-0050 | C |
| AC-80 | Local resume | With resume on, a reload returns to the same attempt, step and answers, except photos, name and e-mail. A copy is refused and removed for a finished, expired, abandoned or other run's token, and expires with the attempt and within 24 hours. "Start again" shows only when the rules allow a new attempt. Resume needs no access code and changes no score, start or questions. | FR-22, ADR-0020, ADR-0050 | C |
| AC-81 | Scoreboard visibility | Hidden by default; live or after the run ends as the admin chooses. With anonymised names a live board shows anonymous labels, which become nicknames after the end; a participant without a nickname is anonymous or not listed. The public page shows no e-mail or internal id. A visible board is refused with the data profile `none` and with answers after each question. | FR-29, ADR-0051 | C |
| AC-82 | Official attempt | One row per browser: the best or the first valid attempt, the earlier of equal scores. Each tie policy gives the same order on every load. | FR-27, ADR-0026, ADR-0051 | C |
| AC-83 | Scoreboard page | The public page refreshes every 15 seconds without a reload and stops when the run has ended and nothing waits for grading; a projector view shows rank, name and score; the own row is marked from the cookie; the result shows the own place. | FR-29, ADR-0051 | C |
| AC-84 | Statistics | A run shows participants, started, submitted and unsent attempts, average, median, lowest and highest score, ten bands, per question numbers under a profile that keeps answers, a split by revision, and the quiz compares its runs; test attempts are excluded. | FR-43 | C |
| AC-85 | Attempts table | The admin attempts table sorts by name, score, time and stored duration, without JavaScript. | FR-29 | C |
| AC-86 | Basic and all | Every settings page shows the same seven groups in the same order. "Basic" hides advanced settings, says how many are hidden, and still shows one whose value differs from what it inherits or was refused; saving in "Basic" keeps the hidden values. The switch works without JavaScript. Quiz tabs are Questions, Runs, Grading, Settings and More. | ADR-0052 | C |
| AC-87 | Run plan | The plan shows its time fields first; each group is collapsed unless it holds a value that differs from the quiz's or a refused one. | FR-10, ADR-0052 | C |
| AC-88 | Pages of questions | A quiz can go through its questions in pages of 2 to 20 (default 5) with going back; the size is fixed when the attempt starts; answers after each question cannot go with pages. | FR-17, ADR-0052 | C |
| AC-89 | Default navigation | A new installation starts with one question at a time and going back; an installation that already has an admin or a quiz keeps all at once, new quizzes included. | FR-17, ADR-0052 | C |
| AC-90 | Reward rules | A run's rules are copied when it is planned or opened from the quiz template, the previous run or nothing, as `reward_source` says; a template change does not reach a planned run and a test run gets none. Threshold (percent, points or correct answers), participation, manual and draw rules have a name, description and claim instructions per language. Their structure is fixed once the run opens, their texts stay editable. Rules are refused with the data profile `none` and with answers after each question, with a message. | FR-36, ADR-0053 | C |
| AC-91 | Entitlements | The server grants an entitlement from the official attempt in the submission transaction, and recomputes it when grading ends or a better attempt becomes official. Under "only the highest" a participant at 70 % and then 92 % with thresholds 70 % and 90 % holds only the 90 % one; under "all" both. A pending attempt grants nothing; a handed-over entitlement and one an admin cancelled are never changed by a recomputation. The result page and the private link show the participant's own rewards with claim instructions in the page's language, else the quiz's default; the quiz page names the run's rewards; nothing is shown without rules. | FR-36, ADR-0053 | C |
| AC-92 | Draw and repeats | On a closed run the admin sees the eligible count and fingerprint, and a draw picks the winners and ranked alternates at once; with fewer eligible it draws everyone and says so, with nobody it stores nothing. Move up takes the first alternate eligible now, substitute draws from those not drawn in the current draw, redraw supersedes the draw; each needs a reason and appends a record, and no earlier record changes. Handed-over entitlements stay. A GET never draws; the audit holds pseudonyms only. | FR-37, FR-38, FR-39, ADR-0013, ADR-0053 | C |
| AC-93 | Contacting winners | Under "warn" the run plan warns when a run with a draw does not ask for an e-mail; under "a draw requires an e-mail" such a run cannot be planned or opened unless the e-mail is required; "no warning" says nothing. The winner's e-mail is shown only on the admin's rewards and draw pages; published winners appear on the scoreboard page by nickname or anonymous label. Entitlements are handed over, cancelled with a reason or granted by hand on the run's rewards page; no e-mail is sent. | FR-36, FR-38, ADR-0053 | C |
