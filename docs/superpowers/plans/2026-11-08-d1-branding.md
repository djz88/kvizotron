# D1 Branding Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One global identity (name, motto, logo, colours, footer) that every quiz inherits field by field and may override; custom colours from two picks, adjusted to WCAG AA with a notice; a fixed "Runs on Kvízotron" line.

**Architecture:** The theme plugin `theme.default` becomes pure owner of the look: it declares `color_palette` (five presets + `custom`) in its manifest, states which branding fields it supports, and derives a full token set from two colours. The domain owns the table `branding_configuration` and resolution (`app/domain/branding.py`), the same split as rewards (ADR-0053) and results (ADR-0051): plugins import only `app.contracts`. `rendering.page` passes one resolved `branding` object to every template instead of `palette`.

**Tech Stack:** Python 3.15, Django 6.1, Jinja2, HTMX, SQLite WAL, plain JS (no build), pytest.

**Spec:** `docs/superpowers/specs/2026-11-08-d1-branding-design.md`

## Global Constraints

- Branch `feat/d1-branding`. Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- `make` needs uv 0.13+: `export PATH=<uv-0.13>/bin:$PATH`.
- `color_palette` keeps its key, stored values, default `blue_teal`, scopes global + quiz with reason "Colours belong to the quiz's pages, and a page holds many questions.", group `look`, level `basic`. New choice `custom` labelled "Custom colours". A key owned twice stops start-up: the domain `CATALOGUE` entry and `settings.Palette` go in the same commit the manifest gains it.
- Branding fields (exact ids): `name`, `motto`, `logo`, `colours`, `footer`. Texts per locale `cs`, `en`, `uk`; empty en/uk → cs; all empty → next level. A text override counts as set when any locale is filled. Footer max 300 characters, plain text. Name max 80, motto max 160.
- Built-in defaults: name "Kvízotron"; motto the existing translated "Turn on your brain. Start Kvízotron."; logo `/assets/logo.svg`; footer empty.
- Palette and custom colours resolve as one unit from the level that chose `custom`. Saving `custom` without both colours is refused: "Choose both colours for custom colours."
- Colours are accepted only as `#rrggbb` (case-insensitive, stored lower-case). Only validated hex reaches CSS; no admin text reaches HTML unescaped or CSS at all.
- Every pair in `tests/test_palettes.py::PAIRS` reaches 4.5:1 in light and dark for derived palettes.
- Adjustment notice text: "The chosen colours do not reach WCAG AA contrast, so they were adjusted. These colours are used:" followed by swatches.
- Kvízotron line text: "Runs on Kvízotron", linking to `url('about')`, on every page that extends `public/base.html`; cannot be turned off.
- Where branding applies: pages that pass `palette_quiz` (play, public quiz/result/walkthrough, scoreboard and projector, preview, test link) use the quiz's; all others use the global one. Rename the context key `palette_quiz` → `branding_quiz` everywhere.
- Duplicating a quiz does not copy its branding, like its other setting overrides (`duplicate_quiz` copies none). Archiving keeps it.
- A replaced or removed logo asset is deleted through `MediaStorageProvider.delete_image` only when no other `branding_configuration` row refers to it.
- Changes take effect immediately, create no draft, and are audited with action `branding.changed`, `details` holding field names only, never values.
- Public texts cs, en, uk; admin texts cs and en, via `make messages`; revert `.mo` changes in untouched modules. A run is `běh` / `run`.
- Phone width, light and dark, keyboard, works without JavaScript (colour inputs degrade to text fields).
- New ADR-0054, new AC from AC-94; each new AC named by a test docstring (`tests/test_docs.py`). Migration `app/domain/migrations/0017_branding.py`.

## Review Focus

1. A quiz overrides only the logo: name, motto, footer and colours still follow later global changes. Tested in Task 2.
2. Global palette `custom`, quiz overrides with preset `red_plum`, then removes the override: the quiz goes back to the global custom colours. Tested in Task 2.
3. Name or footer containing `<script>` or `</style>`: escaped in bar, `<title>` and footer, never inside the `<style>` block. Tested in Task 3.
4. Very light main colour (`#ffff00`) and same main and accent: saving succeeds, notice shown, derived pairs pass AA. Tested in Tasks 1 and 4.
5. Removing the global logo while a quiz uses the same asset id: file kept. Tested in Task 2.
